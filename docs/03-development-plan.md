## 1. 技术方案（推荐）

- 纯前端单页应用：HTML + CSS + 原生 JavaScript（ES Modules），无框架、无构建工具、无后端、无第三方依赖。
- 打开方式：双击 `index.html` 用 Chrome / Edge 打开即可使用，无需安装任何东西。
- 数据存储：IndexedDB（Promise 封装），通过存储抽象层支持一键切换 localStorage 兜底（应对个别浏览器 file:// 限制）。
- 图表：自写轻量 SVG 图表（环形图 / 柱状图 / 折线图），不引入图表库。
- 主题：CSS 变量实现「星空暗色（默认）/ 极简浅色」双主题。
- 路由：hash 路由（`#/home`、`#/today`、`#/journal`…），支持浏览器前进后退。
- 理由：零安装零依赖、数据完全本地可控、后续可平滑迁移到 Tauri/Electron 打包成桌面应用。
- 备选方案（首版不推荐）：Vite + Vue/React，需 Node 环境和构建步骤；若后续界面复杂度明显上升再迁移。

## 4. 全局 UI 约定

- 通用组件：Toast（操作反馈）、Confirm（删除二次确认）、Modal（表单弹层）、空状态（图标+文案+引导按钮）、表单校验（必填、金额>0）。
- 删除必须 Confirm；清空所有数据必须输入「清空」。
- 日期统一 YYYY-MM-DD；金额保留两位小数，输入时过滤非数字。
- 所有写操作经 store 广播变更事件，相关页面自动刷新（首页摘要同步更新）。
- 未开发功能统一 Toast「暂未开发」。

## 5. 开发阶段（每阶段含验收，依据 PRD §10）

### Phase 0 骨架与基础设施
任务：
1. `index.html` 框架：侧边栏（10 个导航项）+ 内容区 + 全局组件挂载点。
2. `theme.css`：星空暗色主题 + 极简浅色变量 + 毛玻璃卡片。
3. `router.js`：hash 路由，10 个页面先渲染占位。
4. `db.js`：IndexedDB 封装（Promise）+ localStorage 兜底开关。
5. `store.js`：通用仓库（增删改查 + 变更事件）。
6. `ui.js`：Toast / Modal / Confirm / 空状态 / 校验组件。
7. `seed.js`：默认预算分类、占位工具与游戏列表。

验收：
- 双击 `index.html` 打开，10 个导航均可切换、无报错。
- 控制台执行数据层读写测试，刷新后数据仍在。
- 页面无任何网络请求。

### Phase 1 今日计划 + 首页总览
任务：
1. 任务增删改查：标题（必填）、时间段（上午/下午/晚上/全天）、优先级、标签、备注。
2. 任务按时间段分组；勾选完成划线并移入已完成区。
3. 日期切换（←/→、今天、日历弹层）查看历史。
4. 「未完成任务顺延到明天」（复制 + 标记已顺延）。
5. 首页：按时段问候、今日前 5 条任务（可勾选）、快速备忘（回车即存、悬停删除）。
6. 首页 6 张摘要卡先显示结构，数据接入放在 Phase 8 统一联调。

验收：PRD §10「今日计划」「首页总览」相关条目全部通过。

### Phase 2 每日手账 + 月度预算（核心模块）
任务：
1. 手账：心情（5 个 emoji）、天气、正文，输入停顿自动保存 +「已保存 HH:mm」反馈。
2. 预算设置：每月预算金额；分类管理（增删改，联动记账下拉）。
3. 记账：记一笔（类型/金额/分类/备注）、流水列表按日期分组、编辑/删除。
4. 预算条：正常（蓝）→ 紧张（黄）→ 超支（红 + 提示超支金额）。
5. 月历：有手账/账目的日期打点，点击日期查看该日内容。
6. 月度报表：分类占比环形图、每日支出柱状图、收支汇总。

验收：PRD §10「每日手账」全部条目通过。

### Phase 3 自媒体
任务：
1. 灵感库：增删改、状态（待用/已采用/放弃）、按状态筛选。
2. 草稿大纲：增删改、状态流转（构思/写作中/待发布/已发布）、可关联灵感（关联后灵感自动变已采用）、发布回填日期。
3. 发布日历：月历视图显示「平台+标题」标签，支持安排/取消排期。
4. 平台账号：增删改。

验收：PRD §10「自媒体」全部条目通过。

### Phase 4 开发工作
任务：
1. 项目列表 + 项目详情页（返回）；项目任务四态切换。
2. 学习主题：增删改 + 进度百分比调整（即时保存）。
3. 问题库：增删改 + 关键字搜索（标题/标签/解决方案）。

验收：PRD §10「开发工作」全部条目通过。

### Phase 5 健身计划
任务：
1. 周计划：周一至周日网格编辑，复制本周 → 下周（覆盖确认）。
2. 训练记录：增删改 + 常用动作快捷选择。
3. 身体数据：增删改 + 体重/体脂折线趋势图。

验收：PRD §10「健身计划」全部条目通过。

### Phase 6 饮食计划
任务：
1. 今日饮食：早/中/晚/加餐记录（内容+热量），顶部总热量实时累加。
2. 饮食记录：历史按日期分组查看。
3. 计划模板：新建、编辑、套用到今天（覆盖前提示）。

验收：PRD §10「饮食计划」全部条目通过。

### Phase 7 占位模块 + 数据与设置
任务：
1. 实用小工具、游戏娱乐：占位网格卡片 + 点击 Toast「暂未开发」。
2. 设置：主题切换（即时生效并记住）、应用名称、预算默认分类。
3. 导出：下载 JSON 备份（全部数据 + 导出时间）。
4. 导入：格式校验 + 覆盖前自动备份当前数据。
5. 清空：输入「清空」确认后清空并回首页。

验收：PRD §10「实用小工具与游戏娱乐」「数据与设置」全部条目通过。

### Phase 8 集成联调与总验收
任务：
1. 首页 6 张摘要卡全部接入真实数据（预算剩余、进行中任务数、待发布草稿数、今日训练、今日饮食、最近体重）。
2. 全量回归 PRD §10 验收清单，逐条勾选。
3. 边界处理：空状态、长文本、非法输入、跨月预算切换、跨周复制。
4. 写 README.md：打开方式、数据存储说明、定期备份建议。
5. 视觉打磨：星空背景、卡片动效、空态插画。

验收：PRD §10 全部条目通过，交付第一版。

## 6. 执行顺序与依赖

- Phase 0 → 1 → 2 为主线，先打通核心闭环（计划 → 手账 → 预算）。
- Phase 3、4 相互独立，在 Phase 2 之后依次完成。
- Phase 5、6 相互独立，在 Phase 4 之后依次完成。
- Phase 7 依赖 Phase 0（占位入口）和 Phase 1（设置持久化）。
- Phase 8 最后做全模块集成与总验收。
- 每个阶段完成后停下做验收，通过再进入下一阶段。

## 7. 测试与验收方式

- 不引入自动化测试框架；每阶段完成后按 PRD §10 对应条目人工逐条验收。
- 数据层关键流程（增删改查、顺延、预算计算、导出/导入）在浏览器控制台提供冒烟测试函数。
- 每个阶段结束前清理测试产生的临时数据。
- 验收记录直接在 PRD §10 清单上逐条打勾留档。

## 8. 风险与对策

- file:// 下 IndexedDB 异常 → 存储抽象层一键切换 localStorage 兜底。
- 原生 JS 代码量大 → 按模块拆分文件、统一复用 store/ui 组件，避免重复代码。
- 图表复杂度 → 仅实现基础 SVG 图表，不追求动画效果。
- 数据丢失风险 → 清空/导入前自动备份；设置页常驻导出入口。
- 长时间手账输入丢失 → 输入停顿自动保存 + 保存时间反馈。
